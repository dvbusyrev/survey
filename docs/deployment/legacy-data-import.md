# Перенос данных из старой базы

Сценарий напрямую читает старую PostgreSQL и записывает преобразованные данные в новую базу. Промежуточный dump на диск не создаётся.

## Что подготовить

В одной папке должны находиться четыре файла:

- `import-legacy-schema.ps1`;
- `prepare-legacy-foreign-schema.sql`;
- `import-legacy-schema.sql`;
- `cleanup-legacy-foreign-schema.sql`.

На компьютере, где запускается перенос, должен быть доступен `psql`. Сервер новой базы должен иметь сетевой доступ к серверу старой базы. В `pg_hba.conf` старого PostgreSQL должно быть разрешено подключение с IP сервера новой базы.

Перед переносом нужно остановить IIS Application Pool и сделать backup новой базы.

## Проверка без записи

Открыть PowerShell в папке со скриптами и выполнить:

```powershell
.\import-legacy-schema.ps1 `
    -SourceConnectionString "Host=OLD_DB_SERVER;Port=5432;Database=old_surveys;Username=OLD_DB_USER;SSL Mode=Require" `
    -TargetConnectionString "Host=NEW_DB_SERVER;Port=5432;Database=surveys;Username=NEW_DB_USER;SSL Mode=Require" `
    -DryRun
```

Скрипт последовательно запросит:

1. пароль пользователя старой БД;
2. пароль пользователя новой БД;
3. временный пароль для импортированных пользователей приложения.

Третий пароль должен содержать не менее 14 символов, строчную и заглавную буквы, цифру и специальный символ. Он применяется только к пользователям, чьи старые пароли несовместимы с текущим ASP.NET Identity.

`DryRun` проверяет структуру, связи, периоды, оценки, дубликаты и конфликты. Данные новой базы при этом не изменяются.

## Выполнение переноса

Если проверка завершилась без ошибок, повторить команду без `-DryRun`:

```powershell
.\import-legacy-schema.ps1 `
    -SourceConnectionString "Host=OLD_DB_SERVER;Port=5432;Database=old_surveys;Username=OLD_DB_USER;SSL Mode=Require" `
    -TargetConnectionString "Host=NEW_DB_SERVER;Port=5432;Database=surveys;Username=NEW_DB_USER;SSL Mode=Require"
```

По умолчанию данные читаются из схемы `public` старой базы и записываются в `public` новой базы. Если таблицы старой базы находятся в другой схеме, добавить параметр:

```powershell
-SourceSchema "legacy"
```

Для чтения старой базы скрипт временно создаёт в новой базе `postgres_fdw`, foreign server и отдельную схему. После проверки или переноса временные объекты удаляются автоматически. Пароли не записываются в файлы и очищаются из переменных окружения после завершения.

## Что переносится

Переносятся организации, пользователи, анкеты, вопросы, назначения, ответы, участники ответов и подписи. Старые адреса организаций и флаг `last_month` не имеют полей в новой модели; их количество выводится в итоговом отчёте.

Назначение анкеты, организация и срок доступа переносятся из `access_to_survey` с привязкой к организации через `io`. Базовый период анкеты рассчитывается по срокам её назначений. Если старое назначение уже удалено, но для него сохранился итоговый ответ, импортёр восстанавливает техническое архивное назначение с периодом из `surveys.start_date` и `surveys.end_date`. Дата ответа используется только как резерв, если период в старой анкете не заполнен. Количество восстановленных назначений выводится отдельно.

Сам импорт выполняется одной транзакцией. Любая ошибка до `COMMIT` откатывает вставленные данные.
